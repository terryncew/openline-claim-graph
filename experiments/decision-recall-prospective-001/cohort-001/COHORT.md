# Prospective Decision Recall Cohort 001

Status: **DESIGNATED — ACTIVATES AFTER THE INSTALL COMMIT — ZERO EMPIRICAL DECISIONS AT INSTALL**

Cohort 001 is the self-hosted natural development stream for `openline-claim-graph`.
It is not a synthetic benchmark and the commit that installs this cohort apparatus
is never eligible.

After installation, ordinary consequential repository decisions are the stream.
A decision counts only when it would have happened without the benchmark. The
instrument may not manufacture work to reach 30 observations, and it may not
prefer decisions that look favorable to dependency graphs.

Eligible examples include real bug fixes, release decisions, dependency changes,
benchmark corrections, CI repairs, behavior-affecting documentation changes, and
accepted or rejected mechanism decisions that create accepted state. Mechanical
bookkeeping is not eligible.

Every post-activation repository commit that changes substantive files must be
represented by a cohort observation or an explicit exclusion. This does not prove
selection neutrality, but it makes silent cherry-picking visible.

## Capture

The normal ship / reject / accept decision is the confirmation event. The agent
prepares the dependency draft and starts the existing monotonic capture surface
before the receiver makes that ordinary decision. No extra research questionnaire
is introduced. Corrections count. The finalized manifest, conventional record,
and cohort observation are included with the accepted change.

A cohort observation binds the manifest to a canonical change-set digest rather
than the Git commit hash. The digest excludes cohort bookkeeping and generated
`MANIFEST.json` / `EVIDENCE.json`, so the observation can be committed with the
change without a hash cycle. Git history can reconstruct the same digest later.

## Frozen-instrument rule

The cohort designation content-addresses the files that determine capture,
challenge, disposition, scoring, and cohort eligibility. If any of those files
change during accumulation, Cohort 001 enters `RESTART_REQUIRED_INSTRUMENT_MUTATED`.
A real instrument-health repair is allowed, but it starts a new cohort. Missing
dependencies, capture friction, Flat Search wins, and bad dispositions are data,
not repair tickets.

## End condition

The cohort accumulates naturally until the existing frozen 0.6.0.dev0 protocol is
eligible to seal: at least 30 real accepted decisions, then the independent
manifest-blind basis catalog and 10 post-seal controlled revocations. No 0.6.0
product promotion exists before the frozen gate fires.

If the repository never naturally produces 30 qualifying decisions, Cohort 001
simply remains incomplete. That is evidence about the proposed indie-operator
wedge, not a reason to manufacture traffic.
